我们刚才为项目添加了一个小功能，但更大的更改需要更完善的流程。GitHub Copilot app 可以配合组织现有的工作流，确保以正确方式构建正确功能。本课将开始一系列课程，按照典型的智能体驱动开发流程，从议题开始生成新功能，确认代码有效、功能符合预期，最后成功合并到项目中。

> [!NOTE]
> 后续功能工作将沿用同一会话。通常会为不同类型的文件创建不同会话或 PR，但本研讨会会采用简化流程，帮助你专注于核心概念。

本课将学习如何：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中明确需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续开发此功能时，你还会更新存储库指令、自定义现有 `quality-checks` 技能、添加 MCP 验证、创建 QA 智能体并创建功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访问者需要按类别和发行商筛选游戏。待办事项中的议题描述了该功能，但组合类别等细节需要在编码前确定。你将使用 Plan 模式明确这些决定，然后授权 Autopilot 在限定范围内实现功能。

## 背景

将 AI 编码智能体引入开发流程不会改变基本原则，反而使这些原则更加重要。多数开发者遵循的流程大致如下：

1. 打开已创建且说明工作要求的议题。
2. 制定构建方案。
3. 编写并审查代码。
4. 运行测试验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程因团队和组织而异，但大多数流程都与上述步骤类似。

坚持采用标准流程，可以确保 AI 生成的代码符合要求，并经过与人工编写代码相同的审查过程。

## 会话模式

**会话模式**控制智能体的自主程度。可以通过提示框下方的下拉菜单设置，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先制定计划。你审查并批准计划后，智能体才开始执行。
- **Autopilot**：智能体完全自主工作，编写代码、运行测试并持续迭代，无需等待输入。

从 Plan 模式开始，审查计划，然后使用 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已合并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。该议题已从模板创建，无需另行创建。
2. 选择 **New session**，并从已更新的 `main` 分支创建**新工作树**。

   ![GitHub Copilot app 中的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果它们在终端中可用，但在会话中不可用，请检查 app 的 PATH 或版本管理器设置，然后完全退出并重新打开 app。重试失败的操作和检查；不要仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划可以在 Copilot 编写代码前审查实现方案。由于会话从议题开始，Copilot 已将功能需求作为上下文。发送：

```plaintext
实现此功能。
```

回答 Copilot 的问题，并根据议题的验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论任何不明确的行为，例如多个类别如何组合，或没有游戏匹配时如何处理。

计划应包括使用项目现有工具运行 lint、单元测试、端到端 (E2E) 测试和类型检查。计划应聚焦于实现和测试筛选功能；完成质量工作流后再创建 PR。批准计划前，请要求 Copilot 修改不合适的部分，并记录议题 URL 及已商定的说明，供后续验证。

## 明确批准 Autopilot

确认计划符合预期后，选择 **Approve and implement this plan**，或当前版本中含义相同的选项。不要假定批准计划会自动切换模式；请确认活动模式指示器显示 **Autopilot**。

Copilot 会开始实现功能，按照计划迭代、生成代码并运行测试。

> [!NOTE]
> 批准后可能会立即开始实现，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

代码生成后，和其他代码一样，合并前需要审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选实现和测试。
2. 根据议题及已批准的说明审查结果，包括多个类别和发行商的组合。确认更改遵循现有存储库指令。
3. 检查 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不算通过。
4. 解决失败项并重新运行受影响的检查，然后再接受实现。Playwright 的 E2E 配置会构建并提供预览服务器，也可能复用本地服务器；确认测试使用的是当前工作树的服务器，而不是前一课遗留的服务器。

## 试用新功能

代码看起来不错，但运行是否正常？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，请求 Copilot 启动应用并在浏览器画布中打开页面：

   ```plaintext
   启动应用并在浏览器画布中打开。
   ```

2. 稍等片刻，应用会启动，浏览器窗口会在 Copilot app 中打开。
3. 选择类别并确认结果符合类别。清除筛选，再选择发行商并确认结果符合该发行商。
4. 同时选择类别和发行商，根据议题和已批准的计划检查结果。如果支持多个类别，还要验证已商定的组合行为。
5. 尝试没有匹配游戏的筛选组合并检查空状态。清除或重置筛选，确认完整列表恢复。
6. 完成后，要求 Copilot 停止此会话启动的开发服务器：

   ```plaintext
   停止开发服务器并关闭浏览器画布。
   ```

## 保留会话供后续课程使用

现在不要创建或合并筛选 PR。保留此会话、工作树和分支，供第 4 到第 8 课继续使用。接下来会将自定义指令应用于筛选代码，再添加技能和 QA 改进，最后在第 8 课创建并合并合并后的 PR。停止开发服务器后，可以让会话保持空闲，并在下一课返回同一会话。
